## 〇、核心判断：这个知识库缺的是"本台实测"

通读 README 13 节 + `references/` 全部分析文件后，一个结构性缺口反复出现：

**知识库里几乎所有关键论断都建立在「外部权威 + 物理推导」之上，极少有 BG1SB 自己天线的实测验证。**

| 论断来源类型 | 例子 | 结论强度 | 本台验证 |
|------------|------|---------|---------|
| 外部 VNA 实测 | ON6URE "80m 磁芯饱和 / 15m 容性" | ⭐⭐⭐ | ❌ 无 |
| 社区共识 | PA9X "EFHW 是 RX 瓶颈不是 TX 瓶颈" | ⭐⭐ | ❌ 无 |
| NEC 建模 | N6CC "每个波段都是不同的天线" | ⭐⭐⭐ | ❌ 无 |
| 物理推导 | "奇次谐波(15m)阻抗失配" | ⭐⭐⭐ | ❌ 无 |
| 估算基准 | deep-dive §6.1 "辐射效率 60-75% / 底噪 S7-S9" | ⭐⭐ | ❌ 无 |

这些数字是**别人的天线、别人的环境、教科书的模型**。BG1SB 架在自己屋顶、接自己馈线、处在自己电磁环境里的那根 EFHW，到底是不是这样——知识库回答不了。

而这恰恰是 PSKReporter 数据的主场：**每一条 FT8 接收报文，都是一次免费的远场探针**。`all_records` 里 7 万+ 接收台、12 万+ 发射台，等于在全球布了几万个校准过的场强计，7×24 小时对着你的天线做方向图测量。把这些数据喂进已有的 8 个 `/api/antenna/*` 端点，就能把上表每一行的"❌ 无"变成"✅ 本台实测值"。

下面按"**理论论断 → 数据里的可观测特征 → 用哪个端点 → 诊断 → 改进动作 → 复测闭环**"逐条展开。

## 一、闭环验证的方法论框架

PSKReporter 数据做天线测量，本质是一套"**自然界的远场暗室**"，但有它的物理边界，必须先讲清楚什么可信、什么是估计。

### 1.1 哪些是硬数据，哪些是模型估计

| 量 | 来源 | 可信度 | 说明 |
|----|------|--------|------|
| **方位角** | 两端 Maidenhead 网格 → 大圆方位 `compute_bearing` | ⭐⭐⭐⭐⭐ **硬数据** | 几何计算，零假设 |
| **距离** | 两端网格 → 大圆距离 | ⭐⭐⭐⭐⭐ **硬数据** | 几何计算 |
| **SNR** | 对端解码器上报 | ⭐⭐⭐⭐ **准硬数据** | 受对端天线/噪声影响，但大样本平均后稳定 |
| **相对 ΔSNR**(对邻居) | 本台 SNR − 同网格邻居 SNR | ⭐⭐⭐⭐ **硬数据** | 差分抵消传播共模，是天线对比的金标准 |
| **仰角** | 距离 → F2@300km 球面模型反推 `elevation_angle_deg` | ⭐⭐ **模型估计** | 单跳假设，多跳/混合模式会偏 |

> **铁律**：凡涉及"方向/方位/相对强弱"的结论 = 可信；凡涉及"绝对仰角度数" = 当趋势看，不当真值用。`polar_pattern` 端点的 note 已经诚实标注了这一点（"角向=实测大圆方位 · 径向=球面模型反推为估计值"）。

### 1.2 为什么"对邻居差分"是闭环的关键

单看自己的 SNR 没意义——今天 20m 开条件好，明天差，全是传播在变。但**同一时段、同一网格(同传播条件)下，你和邻居的 SNR 差(ΔSNR)，剥离了传播，只剩天线 + 馈线 + 功放 + 噪声环境的差异**。

这就是 `weak_spots` 和 `tx_quality` 两个端点的设计灵魂：它们都先取 `sender_locator LIKE 'grid_prefix%'` 的邻居做基准，再算差分。**ΔSNR 才是天线的"体检指标"，绝对 SNR 只是"今天天气"。**

### 1.3 闭环的五个环节

```
①理论论断 ──→ ②数据可观测特征 ──→ ③端点/SQL ──→ ④诊断
                                                      │
   ⑥复测(改造后重新跑同一端点,看ΔSNR是否改善) ←── ⑤改进动作
```

每一节都按这个回路收尾，确保不是"分析完就完了"，而是能驱动真实的天线改造，并用同一把尺子量出改造有没有用。

## 二、逐条论断的数据闭环

### 论断 1：「EFHW 是 RX 瓶颈，不是 TX 瓶颈 / 被听到但听不到回复」(PA9X)

这是 EFHW 用户最大的痛点叙事，但在知识库里是 ⭐⭐ 社区共识，BG1SB 从没量过自己是不是这样。

| 环节 | 内容 |
|------|------|
| **②可观测特征** | 同一根天线、同一时段：你作为 **TX**（`sender_callsign=BG1SB`）被多少远台听到 vs 你作为 **RX**（`receiver_callsign=BG1SB`）听到多少远台。若 TX 覆盖范围 ≫ RX 覆盖范围 → RX 瓶颈被证实 |
| **③端点** | `hop_analysis` 跑两次：`role=tx` 和 `role=rx`，对比 >4000km 占比。代码里 `dx_pct` 逻辑已经预埋了这个非对称性判断 |
| **④诊断** | 端点已内置：`⚠ TX 远距离仅占 X%，如果 RX 能听到大量 DX，说明存在严重非对称性(能听不能叫)`。反过来若 RX 的 DX 占比 ≪ TX，则验证 PA9X 的"RX 瓶颈" |
| **⑤改进** | 若 RX 瓶颈成立 → 上 [[pa9x_txrx_split]] 方案：TX 用 EFHW，RX 加有源磁环(MLA-30+/Wellgood Loop)，配 T/R 切换 |
| **⑥复测** | 加磁环后，RX 跑 `hop_analysis` + `noise_floor`，看 DX 占比上升、底噪下降多少 dB |

**新增建议端点 `/api/antenna/txrx_balance`**：一次查询直接出"TX 听到 N 个 DXCC / RX 听到 M 个 DXCC"的非对称比，把 PA9X 论断变成一个本台数字。

---

### 论断 2：「多波段 EFHW 是营销话术 / 每个波段都是不同的天线」(ON6URE, N6CC)

知识库 ⭐⭐⭐ 物理推导：偶次谐波(20m/10m)落在电流波腹→低阻抗失配，奇次(15m)容性失配，且 N6CC NEC 建模说各波段方向图完全不同。

| 环节 | 内容 |
|------|------|
| **②可观测特征** | 各波段的**主瓣方位**和**方向集中度 R** 应当显著不同；且某些波段(15m/10m)的 ΔSNR vs 邻居应系统性偏低 |
| **③端点** | `lobe_drift`（圆形统计出每波段 mean_azimuth + 集中度R + 跨波段一致性诊断） + `weak_spots`（每波段×方向 ΔSNR） |
| **④诊断** | `lobe_drift` 已能输出 `主瓣方位随波段漂移(离散±X°) → 不同波段不同天线`。若 15m/10m 在 `weak_spots` 里系统性 Δ≤-2dB → 验证奇次谐波/高次失配 |
| **⑤改进** | 确认某波段失配 → ①该波段加单波段天线；②或上 [[efhw_ac_dual_mode]] A+C 双模(Unit C 专攻 30m-10m)；③15m 可加 LC 补偿 |
| **⑥复测** | 改造后重跑 `weak_spots`，看目标波段 ΔSNR 是否回到 0 附近 |

**这是知识库最值得验证的论断**：N6CC 的 NEC 建模是仿真，PSKReporter 的 `lobe_drift` 是**你这根天线在真实电离层下的方向图投影实测**。如果实测各波段方位漂移 ±60°，N6CC 就在你的天线上被证实了——而且是用真数据，不是仿真。

---

### 论断 3：「辐射效率 60-75% / QRM 底噪 S7-S9」(deep-dive §6.1 估算基准)

这两个数是知识库里最该被替换的——它们是**估算**，挂在那当基准用，但从没量过 BG1SB 的真实值。

| 环节 | 内容 |
|------|------|
| **②可观测特征** | "效率"无法直接测绝对值(没有参考天线)，但**相对效率 = ΔSNR vs 邻居**可测：若全波段全方向系统性 -3dB，约等于辐射效率比邻居低一半(3dB=2×功率)。底噪则看 RX 各方位最低 SNR |
| **③端点** | `weak_spots`（全局 avg_delta 当相对效率指标） + `noise_floor`（每方位 min_snr / p5_snr，`noise_warning` 标记 min>-18dB 的疑似噪声方向） |
| **④诊断** | `weak_spots` 的 `avg_delta` 若为 -3dB → 本台天线系统比邻居低 3dB(可能是 49:1 损耗/馈线/地网)。`noise_floor` 直接给出"最安静方向能听到 X dB"——这就是底噪的实测代理 |
| **⑤改进** | 全局 -3dB → 查变压器(换更低损耗磁芯/线径)、馈线接头、地网/counterpoise。底噪高的方向 → 找该方位的本地干扰源(开关电源/PLC) |
| **⑥复测** | 把 deep-dive §6.1 的 "60-75%"/"S7-S9" 估算，替换成本台实测的 `avg_delta` 和 `noise_floor` 数值，知识库基准从⭐⭐升到⭐⭐⭐⭐ |

---

### 论断 4：「EFHW 发射仰角过高，不利 DX」(EFHW 通病)

水平/倾斜 EFHW 常被诟病高仰角辐射，吃亏在 DX。

| 环节 | 内容 |
|------|------|
| **②可观测特征** | 远距离(>4000km, 必然低仰角到达)报文的占比；以及 `band_angle` 各波段的 p10/p50/p90 仰角分布 |
| **③端点** | `band_angle`（每波段 median_angle + 类型标注 DX低仰角/中距离/NVIS高仰角） + `hop_analysis`（双跳/多跳占比） |
| **④诊断** | 若 40m/80m 的 p50 仰角 >20° 且 DX 占比 <10% → 验证"高仰角、偏 NVIS"。注意：仰角是模型估计，所以**以"DX 占比"硬数据为主，仰角度数为辅** |
| **⑤改进** | 抬高架设、改垂直/倒 L 构型、或针对 DX 波段加低仰角天线 |
| **⑥复测** | 改造后 `hop_analysis` 看 >4000km 占比是否提升 |

---

### 论断 5：「Counterpoise / 共模电流影响」(AA5TB 核心)

AA5TB 整篇在讲 0.05λ counterpoise 与共模控制，是 ⭐⭐⭐⭐⭐ 理论，但"我家这根装好后共模到底大不大"没数据。

| 环节 | 内容 |
|------|------|
| **②可观测特征** | 共模电流会让方向图畸变、SNR 抖动增大。表现为：同一接收台多次报文的 SNR 标准差异常大；或方向图出现非物理的不对称 |
| **③端点** | `tx_quality`（per-receiver SNR variance，已内置`同一接收台SNR抖动>8dB → 天线受风摆/极化不稳`诊断） + `polar_pattern`(看方向图对称性) |
| **④诊断** | 若 `rx_variance` 普遍 >8dB 且 `my_std > peer_std×1.5` → 系统不稳定，疑似共模电流/匹配漂移(呼应 AA5TB"触摸馈线改变SWR=调谐不良"的判据) |
| **⑤改进** | 加共模扼流圈(1:1 choke)、调整 counterpoise 到 0.05λ、检查 49:1 接地 |
| **⑥复测** | 重跑 `tx_quality`，看 SNR 标准差和 rx_variance 是否收敛 |

---

### 论断 6：「80m 磁芯饱和 / 低频电感不足」(ON6URE, VA3KOT 复现失败)

| 环节 | 内容 |
|------|------|
| **②可观测特征** | 80m/160m 波段：报文数极少、ΔSNR 大幅落后、或干脆没有数据(调不出谐振用不了) |
| **③端点** | `weak_spots` + `band_angle`（看 80m 是否在 band 列表里、count 多少、delta 多负） |
| **④诊断** | 若 80m 报文数≈0 或 Δ≤-4dB → 验证低频电感不足/磁芯饱和 |
| **⑤改进** | 换更大磁芯(FT240→更大)、增加匝数、或 80m 单独加天线 |
| **⑥复测** | 重跑看 80m count 和 delta |

## 四、要补的两个新端点(让闭环更顺)

现有 8 个端点已能覆盖全部论断，但有两处值得补，把"跑两次手动对比"变成"一次出结论"：

### 4.1 `/api/antenna/txrx_balance` — 一键 TX/RX 非对称比(验证论断1)
```
SELECT
  COUNT(DISTINCT CASE WHEN role=tx THEN dxcc END) as tx_dxcc,
  COUNT(DISTINCT CASE WHEN role=rx THEN dxcc END) as rx_dxcc,
  ... 按 hop bin 分层
→ 输出: tx_reach / rx_reach 比值, 直接判定"能叫不能听"还是"能听不能叫"
```

### 4.2 `/api/antenna/efficiency_proxy` — 相对辐射效率代理(验证论断3)
```
取 weak_spots 的全局 avg_delta(对同网格邻居)
→ Δ转功率比: efficiency_ratio = 10^(avg_delta/10)
→ 输出: "本台天线系统相对邻居中位数效率 ≈ XX%" (替换 deep-dive §6.1 的估算)
```

> 两个端点都是对现有 `weak_spots`/`hop_analysis` 逻辑的轻量聚合，半天工作量。

## 七、结论

1. **效率/效果如何提升**：靠 `weak_spots` 找出本台相对邻居系统性落后的"波段×方向"组合(ΔSNR≤-2dB)，逐个归因(磁芯损耗/馈线/方向图凹陷/本地噪声)并改造——这是数据驱动的天线优化，而非凭感觉换件。

2. **如何闭环验证**：用"对同网格邻居差分(ΔSNR)"剥离传播变量，改造前存基线、改造后复测同一端点，ΔSNR 的变化就是改造效果的客观度量。`tx_quality`/`weak_spots` 的邻居基准设计正是为此。

3. **如何找待提升问题**：把知识库 6 大⭐⭐–⭐⭐⭐ 理论论断，逐条映射到已部署端点的硬指标上跑实测——凡是本台数据背离理论或显著落后邻居的地方，就是待提升的问题。其中**论断2(多波段=不同天线，用 `lobe_drift` 实测方位漂移)** 和 **论断1(RX瓶颈，用 `hop_analysis` 对比 tx/rx DX占比)** 是最高价值、当下即可验证的两个切入点。

**最大的认知转变**：efhw-knowledge 至今是一座"借来的理论"图书馆；PSKReporter 数据让 BG1SB 第一次能在自己的天线上、自己的环境里，把这些理论**证实、证伪或修正**。知识库的下一次跃迁，是从 `references/`(别人说) 长出 `measurements/`(我测了)。
